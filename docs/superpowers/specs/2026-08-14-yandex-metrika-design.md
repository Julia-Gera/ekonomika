# Интеграция Яндекс Метрики

## Цель

Подключить счётчик Яндекс Метрики `111598594` ко всему Next.js-приложению. Метрика должна начинать работу сразу после гидратации страницы, без запроса согласия через cookie-баннер, и корректно учитывать переходы App Router без полной перезагрузки.

## Границы задачи

В задачу входят загрузка счётчика, исходные настройки из предоставленного Яндексом кода, резервный `noscript`-пиксель и регистрация просмотров при клиентской навигации.

Настройка целей, пользовательских событий, электронной коммерции, интерфейса согласия и изменение политики конфиденциальности в эту задачу не входят. Параметр `ecommerce: "dataLayer"` сохраняется из исходного кода, но новые события электронной коммерции не добавляются.

## Архитектура

Интеграция состоит из двух небольших компонентов:

1. `YandexMetrika` отвечает за глобальную загрузку и инициализацию счётчика. Он использует `next/script` со стратегией `afterInteractive`, сохраняет параметры `ssr`, `webvisor`, `clickmap`, `ecommerce`, `accurateTrackBounce` и `trackLinks`, а также выводит `noscript`-пиксель.
2. `YandexMetrikaNavigation` — изолированный клиентский компонент. Он наблюдает за изменениями пути и строки запроса и отправляет метод `hit` после внутренних переходов Next.js.

Оба компонента подключаются один раз из корневого `src/app/layout.tsx`. Клиентский наблюдатель размещается под `Suspense`, поскольку чтение строки запроса в App Router может приостанавливать статический рендеринг.

Номер счётчика хранится в именованной константе рядом с интеграцией. Это публичный идентификатор, переданный в готовом сниппете, поэтому отдельный секрет или новая обязательная переменная окружения не нужны.

## Поток данных

1. При первом открытии страницы Next.js гидратирует приложение.
2. Встроенный `Script` создаёт очередь `window.ym`, асинхронно загружает `https://mc.yandex.ru/metrika/tag.js?id=111598594` и вызывает `ym(111598594, "init", ...)` с исходными параметрами.
3. Начальный просмотр отправляется самим счётчиком. Клиентский наблюдатель пропускает свой первый эффект, чтобы не создать дубликат.
4. После клиентского перехода наблюдатель формирует текущий URL из `window.location.href` и вызывает `ym(111598594, "hit", currentUrl, { title, referer })`.
5. Предыдущий URL сохраняется в `useRef` и передаётся как `referer` следующего просмотра.

## Отказоустойчивость

- Если скрипт заблокирован расширением браузера или сетью, остальные компоненты сайта продолжают работать.
- Навигационный наблюдатель проверяет наличие `window.ym` перед вызовом и не выбрасывает ошибку, если Метрика недоступна.
- Счётчик и скрипт создаются только один раз в корневом layout.
- Для браузеров с отключённым JavaScript остаётся скрытый `noscript`-пиксель Яндекса.

## Проверка

После реализации необходимо:

1. Запустить `npm run lint`.
2. Запустить `npm run build` для проверки Server Components, `Suspense` и статического рендеринга.
3. Открыть приложение в браузере и убедиться, что запрос `tag.js?id=111598594` выполняется один раз.
4. Проверить наличие первоначального просмотра и отдельного `hit` после перехода по внутренней ссылке без полной перезагрузки.
5. Убедиться, что при блокировке `mc.yandex.ru` страницы и навигация продолжают работать без ошибок.

## Критерии готовности

- Метрика подключена на всех маршрутах.
- Сохранены все параметры предоставленного кода счётчика.
- Первый просмотр не дублируется.
- Клиентские переходы учитываются как отдельные просмотры.
- Интеграция не добавляет новых зависимостей и не влияет на работу сайта при недоступности Яндекса.
